ROOT_CAUSE
V2 proved the comparator settle and pre-start GPIO15 gate, but the initial
accelerated Profile-C charge still tripped after about five completed cycles.
PWM_PrepareStart wrote TBCTR while TBCLK remained running before the later OST
release, so the actual release phase was not deterministic. AQCSFRC was also
left at its reset shadow-load-at-ZRO behavior and the continuous AQ force was
removed without first defining AQ-A in front of the active-high-complementary
dead-band. The first physical interval could therefore depend on the live
time-base/AQ state instead of the requested phase.

PRIMARY_REFERENCE
Texas Instruments TMS320F2803x Real-Time Microcontrollers Technical Reference
Manual, SPRUI10: https://www.ti.com/lit/ug/sprui10/sprui10.pdf
Relevant facts audited: AQSFRC supports one-time software actions; RLDCSF=3 is
immediate continuous-software-force loading; AQ precedes the dead-band block;
trip-zone forcing remains after dead-band and therefore remains the final
physical-output authority.

V3_CHANGE
- PWM_PrepareStart selects AQCSFRC immediate mode and stores prepared phase+1
  in the existing nonzero preparation token (no RAM added).
- PWM_StartDeterministic releases the continuous AQ override while OST is
  still latched, readback-gates that release, then in the real release critical
  section writes AQ-A one-time SET, rewrites TBCTR to the prepared phase, issues
  OTSFA, and only then clears OST.
- The NE-only mirror executes the same seed/TBCTR sequence but deliberately
  never clears OST, then restores the clamp.
- The legacy Burst restart caller now treats the encoded token as nonzero,
  preserving compatibility.

UNCHANGED
Comparator/TZ/DAC threshold; GPIO qualification; frequency and dead-time;
W3 raw thresholds; packet maximum 15 cycles; production envelope; protection
authority; no automatic retry.
